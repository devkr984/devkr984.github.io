PHP 업그레이드

서버 호스팅사에서 “PHP 버전 업그레이드 안내” 메일이 왔을 때 대처법

P PHP.LAB 개발팀 · 2026.11.11 · 6분 분량

어느 날 호스팅사에서 "PHP 버전 업그레이드 안내" 메일이 도착했습니다. 내용은 대부분 "○월 ○일까지 PHP 버전을 올리지 않으면 서비스가 제한되거나, 일괄 변경될 수 있습니다" 같은 식입니다. 개발자가 아니라면 무슨 뜻인지, 지금 당장 무엇을 해야 하는지 막막하기 쉽습니다.

이 글에서는 이런 메일을 받았을 때 무엇부터 확인하고, 어떤 순서로 대응하면 사이트가 멈추지 않는지 정리했습니다.

1. 먼저, 메일이 진짜인지 확인하세요

PHP 업그레이드 안내를 사칭한 피싱 메일도 있습니다. 링크를 누르기 전에 아래를 확인하세요.

  • 발신 주소가 평소 호스팅사에서 오던 도메인과 같은지
  • 메일 속 링크를 누르지 않고, 호스팅사 사이트에 직접 접속해 로그인한 뒤 공지사항에 같은 내용이 있는지
  • 비밀번호·카드 정보 입력을 요구하지 않는지 (정상적인 PHP 안내 메일은 이를 요구하지 않습니다)

2. 메일에서 꼭 확인할 3가지

  • 변경 일정 — 언제부터 적용되는지, 자동 변경인지 직접 변경해야 하는지
  • 대상 버전 — 현재 사용 중인 버전에서 어떤 버전으로 바뀌는지 (예: 7.x → 8.x)
  • 유예 방법 — 호스팅 관리자 패널에서 버전을 선택하거나 일정 기간 유지할 수 있는지

자동 변경인 경우 일정이 지나면 사이트가 갑자기 오류 화면(500 에러, 흰 화면)으로 바뀔 수 있으므로 일정 전에 반드시 점검해야 합니다.

3. 내 사이트의 현재 상태 파악하기

  • 호스팅 관리자 패널에서 현재 PHP 버전 확인
  • 사이트가 어떤 방식으로 만들어졌는지 확인 (그누보드, 워드프레스, 자체 제작 등)
  • 사용 중인 플러그인·스킨·외부 라이브러리가 새 버전을 지원하는지 확인

특히 오래전에 만든 사이트나 구형 그누보드4 기반 홈페이지는 최신 PHP에서 제거된 함수를 쓰고 있는 경우가 많아, 버전만 올리면 바로 오류가 날 수 있습니다. 관련 내용은 구형 그누보드4 PHP 버전 업그레이드 글에서 자세히 다뤘습니다.

4. 대처 순서: 백업 → 테스트 → 전환

운영 중인 사이트에서 바로 버전을 바꾸지 마세요. 문제가 생기면 방문자와 고객이 그대로 오류 화면을 보게 됩니다.

1단계. 전체 백업

소스 파일 전체와 데이터베이스를 백업합니다. 호스팅사의 자동 백업에만 의존하지 말고, 직접 내려받은 사본을 따로 보관해 두세요.

2단계. 테스트 환경에서 새 버전으로 점검

복사본을 별도 경로나 서브도메인에 올려 새 PHP 버전으로 실행해 봅니다. 메인 화면, 로그인, 게시판 글쓰기, 결제, 파일 업로드, 관리자 페이지처럼 핵심 기능을 하나씩 확인합니다.

3단계. 오류 로그 확인 및 수정

화면에 오류가 보이지 않더라도 에러 로그에는 경고(Deprecated, Warning)가 쌓여 있을 수 있습니다. 로그를 확인해 제거된 함수나 호환되지 않는 코드를 수정합니다.

4단계. 이용자가 적은 시간대에 전환

수정과 검증이 끝나면 접속량이 적은 새벽이나 주말 시간대에 PHP 버전을 변경하고, 전환 직후 주요 기능과 오류 로그를 다시 확인합니다.

5단계. 문제 시 되돌릴 방법 준비

전환 후 문제가 생기면 이전 버전으로 즉시 되돌릴 수 있도록 관리자 패널의 버전 설정 위치와 백업 복원 방법을 미리 확인해 둡니다. 단, 이전 버전이 계속 제공되는 기간이 한정적일 수 있습니다.

5. 하지 말아야 할 대응

  • "지금 잘 되니까" 하고 메일을 무시하기 — 자동 변경 시 사이트가 중단될 수 있습니다.
  • 백업 없이 운영 서버에서 바로 버전 변경하기
  • 오류가 난다는 이유로 오래된 버전으로 계속 버티기 — 보안 패치가 끊긴 버전은 해킹 위험이 커집니다. 자세한 내용은 PHP 보안 패치를 미루면 안 되는 이유를 참고하세요.
  • 출처를 알 수 없는 "자동 업그레이드 프로그램"이나 외부 파일 설치하기

6. 직접 하기 어렵다면

코드 수정이 필요한 경우나 제작 업체와 연락이 끊긴 사이트라면 일정 안에 혼자 해결하기가 쉽지 않습니다. 이럴 때는 일정이 촉박해지기 전에 전문가에게 호환성 진단부터 요청하는 편이 비용과 위험을 줄입니다. 호스팅을 옮기면서 함께 정리하는 방법은 호스팅 이전 서비스에서, 이후 정기 관리는 웹사이트 유지보수에서 맡아 드립니다.

마무리

호스팅사의 PHP 업그레이드 안내는 "곧 서버 환경이 바뀐다"는 사전 경고입니다. 메일 진위 확인, 일정 파악, 백업, 테스트, 전환 순서만 지키면 대부분 큰 문제 없이 넘길 수 있습니다. 안내 메일을 받았는데 어떻게 해야 할지 모르겠다면, 일정이 다가오기 전에 점검을 받아보세요.
